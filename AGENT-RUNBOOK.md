# Инструкция для ИИ-агента

---

## Роль агента

Агент **не управляет процессом**, а **исполняет его через CLI**.

Запрещено:

* редактировать JSON/MD файлы в каталогфх ".utep" и "Goals" напрямую
* менять статусы без CLI
* выполнять задачи без `next`

---

## Начало работы

Когда тебе дают задание, ты должен в первую очередь определить цель задания, и проверяемые критерии её успешного достижения.
Всё это ты тодлжен провалидировать у пользователя и после подтверждения цели фразой "Цель подтверждаю" выполняй работу по протоколу UTEP для фиксации цели, критериев успеха, гипотез и результатов их проверки.

```text
1. utep diagnose
2. если E450: Repo not initialized:
     инициализировать utep
3. создать текущую цель если она ещё не существует
4. выбрать текущую цель
```

## Основной цикл агента

```text
1. utep next --count 5 --json
2. если actionable пуст и reason == "none" → остановиться
3. выбрать первую задачу
4. utep task show <id> --json
5. Проверка актуальности
     если неактуально → invalidate/cancel
6. Действие по effective_state:
     Continue → продолжить выполнение, utep task attempt <id>, при критериях → complete
     Execute → utep task start <id>, выполнить, utep task attempt <id>, при критериях → complete
     Clarify → utep task question ..., задать вопрос, дождаться ответа, utep task answer ...
     Plan → оформить задачу (title/success_criteria/deps), при готовности → set-status Ready
     Blocked → работать с блокерами (utep bottlenecks/utep task deps)
7. index.md обновляется автоматически; при необходимости `utep render` или `utep report`
8. utep diagnose
9. перейти к шагу 1
```

---

## Работа с неопределённостью
Каждый шаг ты должен валидировать гипотезы в виде задач и определять что они продвигают тебя к цели.
Если в процессе выполнения появились новые гипотезы или инсайты по достижению цели или критериям успеха, их необходимо фиксировать.
Если задача содержит высокую неопределённость и ты можешь сформировать несколько гипотез как её разрешить, запиши их все в виде задач, оцени какая даст наибольший вклад в достижение цели и начни проверять её.
Если дальше невозможно продолжать без решения пользователя:

1. Сформировать вопрос **с вариантами**
2. Сохранить вопрос через `utep task question`
3. Вывести вопрос пользователю
4. После ответа зафиксировать через `utep task answer`
5. Проверить, уменьшает ли ответ неопределённость и понятно ли, что делать дальше
6. Если нет — добавить уточняющие вопросы через `utep task question`
7. Остановиться до ответа

---

## Лимиты

Если:

* превышен лимит попыток
* превышено разумное время

→ **остановиться**, заблокировать задачу и запросить решение.

---

## Обязательные проверки

Перед каждым `task start` посмотреть содержимое задачи и принять решения по следующим вопросам:

* задача всё ещё актуальна?
  * если нет, то инвалидировать задачу
* цель и критерии успешности не изменились?
  * если да, то проверить что задача ведёт к ним
    * если не ведёт, инвалидировать задачу
* зависимости от других задач действительно сняты?
  * если нет, то перейти к первой блокуирующей задаче
* `success_criteria` заполнены?
  * если нет, то сформулировать и записать их
* `dependencies.blocked_by` явно указан (даже если пустой)
  * если нет, то проанализировать другие задачи, определить какие блокируют и заполнить

## Обязательные поля

* `success_criteria` — задавать при `utep task new --success ...` или при `utep task set-status ... --success ...`
* `open_questions` — только через `utep task question ...`, ответ через `utep task answer ...` (статус `Question`)
* `dependencies.blocked_by` — через `utep task dep add|rm ...`, пустой список допустим

---

## Запрещённые действия

* пропуск `Question`
* автоматическое закрытие задач без evidence
* выполнение задач не из `next`
