# Спецификация (Quest): Actionable для всех нетерминальных задач

## 1. Цель
- Сделать так, чтобы `utep next` возвращал все задачи, над которыми нужно работать: выполнять, уточнять, актуализировать и планировать (включая `Planned`).
- Обновить алгоритм в ранбуке: перед любыми действиями проверять актуальность, затем выбирать тип работы (выполнение vs метазадачи протокола).

## 2. Текущее состояние (AS-IS)
- `utep next` выбирает только задачи с `EffectiveState == "Actionable"` (фактически `Ready` + без блокировок).
- `TaskComputed.EffectiveState` ограничен значениями: `Actionable`, `Blocked`, `Question`, `Terminal`, `NotReady`.
- В основном цикле ранбука предполагается, что если actionable пусто — агент идёт в ветки `question/blocked/none`.

## 3. Проблема
- В выборке `next` отсутствуют задачи, которые нужно уточнять/перепланировать (`Planned`, `Draft`, `Question`), хотя это тоже работа агента/пользователя.
- Из-за этого агент видит «нет actionable», хотя по факту нужно выполнять мета-работу протокола (уточнения, актуализация, планирование).

## 4. Целевое состояние (TO-BE)
- `utep next` включает все нетерминальные задачи, требующие работы, и классифицирует их по типу действия.
- `TaskComputed.EffectiveState` расширен и отражает разные виды действия.
- `utep task start` по‑прежнему доступен только для `Ready` + unblocked; остальные типы `actionable` — это метазадачи (уточнение/планирование/актуализация).
- Ранбук описывает единый цикл с проверкой актуальности и дальнейшей маршрутизацией по типу задачи.
- `utep next` возвращает `reason == "none"` только если нет ни одной нетерминальной задачи; иначе `reason == null`.
-
  Новые значения `EffectiveState` (CLI output-only):
  - `Execute` — `Ready` + unblocked, можно выполнять.
  - `Blocked` — `Ready` + есть активные блокеры, требуется разрулить блокировку.
  - `Continue` — `InProgress`, требуется продолжать выполнение.
  - `Clarify` — `Question` (или `Question` без вопросов как ошибка), требуется уточнение.
  - `Plan` — `Draft`/`Planned`, требуется оформление и прояснение плана.
  - `Terminal` — `Completed`/`Cancelled`/`Invalidated`.

## 5. Non-Goals
- Не меняем модель хранения данных в JSON-файлах задач.
- Не меняем терминальные статусы и их семантику.
- Не вводим новый CLI-командный интерфейс; меняем поведение существующих команд и их документированную спецификацию.

## 8. Бизнес-правила
- `Actionable` — это все нетерминальные задачи, над которыми требуется работа (выполнение или мета-работа протокола).
- Выполнение (execution) допускается только для `Ready` + unblocked.
- Перед любым действием агент обязан проверить актуальность задачи (есть ли смысл выполнять/планировать в текущем виде).
-
  Правило классификации:
  - `Ready` + unblocked → `Execute`
  - `Ready` + blocked → `Blocked`
  - `InProgress` → `Continue`
  - `Question` → `Clarify`
  - `Draft`/`Planned` → `Plan`
  - терминальные → `Terminal`
-
  Правило сортировки `utep next`:
  1. `EffectiveState` в порядке `Continue` → `Execute` → `Clarify` → `Plan` → `Blocked`.
  2. `depth` ↑
  3. `blocks_count` ↓
  4. `priority` ↑
  5. `task_id` ↑ (стабильный tie-break)

## 9. Обработка ошибок
- Попытка `utep task start` для задач, не являющихся `Ready` + unblocked, должна возвращать ту же ошибку `NotActionable` с понятной причиной.
- Ошибки валидации статусов и зависимостей остаются без изменений.

## 10. Производительность
- Алгоритм выбора `next` остаётся линейным по числу задач с прежними сортировками.
- Добавление новых типов `EffectiveState` не должно ухудшать асимптотику.

## 11. Изменения модели данных
- Изменяется только вычисляемый `EffectiveState` в CLI-выводе; файлы `*.task.json` не меняются.
- Требуется обновить описание `EffectiveState` и `NextResult` в `UTEP-SCHEMA.md`/`UTEP-SPEC.md`.

## 12. План миграции

## 14. Критерии приёмки
- `utep next` возвращает все нетерминальные задачи: `Draft`, `Planned`, `Ready`, `Question`, `InProgress`.
- В `utep next` каждая задача помечена `EffectiveState` из списка: `Execute`, `Blocked`, `Continue`, `Clarify`, `Plan`, `Terminal`.
- `utep task start` по‑прежнему допускается только для `Ready` + unblocked.
- Документация (`UTEP-SPEC.md`, `UTEP-SCHEMA.md`, `AGENT-RUNBOOK.md`) синхронизирована с поведением.
- Добавлены/обновлены unit-тесты для `NextSelector` и `TaskComputedBuilder`.
